# Builder brief template (Aftercare style)

```
Repo: <owner/repo>, base <main>. Create a NEW self-contained app in `<folder>/`.
Do not modify <existing apps/configs>; zero deletions outside `<folder>/`.

Vision (keep in PLAN.md, in the user's words): <quote>.

First slice (MVP, build all of it):
1. <feature: user-visible, testable>
2. <signature interaction, with phone behaviour and a fallback>
3. <feature>
4. <feature>
5. Tests, docs, screenshots (below)

Out on purpose (leave room in the data model): <later items>, accounts, server storage,
payments, AI-generated content, third-party runtime APIs, native apps.

Stack guidance: static output (e.g. Astro), TypeScript, minimal/no UI framework,
<specialist lib> confined to one module, data baked at build time, localStorage with
export/import. Pick current stable versions.

Design: propose a NAMED art direction (palette hex, type, ornament, motion, reduced
motion). Reuse brand fonts/colours found in the repo. Full-page mockups, desktop
1440x900 and mobile 390x844, committed BEFORE app code. Original content/art only,
generated by code where possible.

Deliverables: docs/PLAN.md (vision, guardrails, keep table, phases, in/out, data model,
architecture, art direction, milestones, risks), docs/RESEARCH.md (licensing/domain rules),
docs/URL_SHEET.md, docs/mockups/, docs/process/ screenshots per milestone + CAPTIONS.md,
<folder>/README.md.

Verification (all before opening the PR): unit tests for every pure module; typecheck +
full build (report page count); Playwright smoke tests on desktop and mobile projects
(software GL flags if WebGL); screenshot script with seeded sample data; fix what the
screenshots show; no horizontal scroll at 390px.

Guardrails: open one PR; no merge, no deploy, no secrets, no runtime third-party calls,
no copyrighted assets. <domain disclaimer>. <tone rules>.

PR body: What this is / What's in it / How to run / Tests (counts) / Rules followed /
Known weak spots.
```
